## 2. ХОД МЫСЛЕЙ И ПРИНЯТЫЕ РЕШЕНИЯ (АРХИТЕКТУРА)

### Пункт 1. Среда выполнения (Local)
Проект остается строго локальным. Никаких удаленных серверов, сетевых запросов или внешних API во время работы программы. 
Взаимодействие только через терминал (консольный интерфейс).

### Пункт 2. Источник данных (External DB)
Ручное заполнение базы (хардкод) исключается, так как это неэффективно и не соответствует реальным задачам. 
Принято решение скачать готовый набор данных (датасет) и распарсить его. Это демонстрирует навыки работы с файлами и обработки данных.

### Пункт 3. Инструмент хранения (SQLite)
Написание собственного парсера и алгоритмов поиска на чистом C — это «танк против воробья». 
Для оптимизации времени и получения промышленного решения используется встраиваемая СУБД SQLite.
- SQLite не требует установки сервера.
- Вся база данных — это один файл.
- В C-коде структура `struct Book` используется как DTO (Data Transfer Object): 
мы забираем данные из SQLite, мапим в структуру и выводим на экран. ТЗ (использование структур на C) при этом выполняется.

### Пункт 4. Управление ресурсами (Stack vs Heap)
Управление памятью делегируется движку SQLite.
- Стек используется только для управляющих структур (указатели на дескрипторы БД, счетчики).
- Куча и выделение памяти под массивы данных находятся под контролем SQLite (он сам запрашивает память у ОС, если нужно).
- Алгоритмы поиска и сортировки делегируются SQL-запросам (операторы `LIKE` и `ORDER BY`). Это избавляет от необходимости писать 
алгоритмы сортировки вручную и защищает от ошибок с переполнением буфера.

### Пункт 5. Поле поиска
Поиск ключевого слова выполняется строго по полю «название книги» (title). 
Поиск по другим полям (авторы, ISBN, год) не производится. Реализуется как поиск подстроки (вхождение) через SQL-оператор `LIKE`.

Заметки
Чтобы твоя программа могла использовать SQLite, в Makefile нужно добавить флаг линковки -lsqlite3. 
Теперь компилятор будет знать, где искать функции SQLite.

API (Три кита)
Вся работа с SQLite в C строится на трех главных функциях и одной структуре.
sqlite3 *db — это указатель на объект «соединение с базой данных». Через него ты общаешься с БД.
sqlite3_open() — открывает (или создает) файл базы данных. Если файла нет, SQLite его создаст. Функция возвращает код SQLITE_OK, 
если всё прошло успешно.
sqlite3_exec() — выполняет простые SQL-запросы, которые не возвращают данных (например, CREATE TABLE, INSERT, UPDATE, DELETE). 
Она принимает строку с SQL-командой и выполняет её.
sqlite3_close() — закрывает соединение с базой данных, когда работа закончена.

«Продвинутый» уровень — Подготовленные выражения (Prepared Statements)
sqlite3_exec() хорош для простых команд, но для запросов с параметрами (особенно если эти параметры вводит пользователь) нужно 
использовать подготовленные выражения. Это не только удобнее, но и безопаснее (защищает от SQL-инъекций).
Рабочий процесс выглядит так:
sqlite3_prepare_v2() — «компилирует» SQL-запрос. Ты передаешь ей строку с запросом (возможно, с символами ? вместо значений) 
и получаешь указатель на «подготовленный оператор» (sqlite3_stmt *stmt).
sqlite3_bind_*() — если в запросе были ?, ты «привязываешь» к ним конкретные значения (строки, числа). 
Это и есть безопасная подстановка параметров.
sqlite3_step() — «шагает» по результатам запроса. Ты вызываешь её в цикле while. Она возвращает SQLITE_ROW, пока есть строки для 
чтения, и SQLITE_DONE, когда данные закончатся.
sqlite3_column_*() — внутри цикла, когда sqlite3_step() вернула SQLITE_ROW, ты можешь читать данные из текущей строки через эти функции.
sqlite3_finalize() — освобождает память, занятую подготовленным оператором.

Урок 5: Пример для понимания (Не для копирования!)
Вот как выглядит процесс создания таблицы и вставки данных, чтобы ты увидел последовательность.
Создание таблицы (через sqlite3_exec):
c
sqlite3 *db;
sqlite3_open("library.db", &db); // Открыли БД

const char *sql_create = "CREATE TABLE IF NOT EXISTS books ("
                         "id INTEGER PRIMARY KEY, "
                         "title TEXT, "
                         "author TEXT);";

char *err_msg = 0;
int rc = sqlite3_exec(db, sql_create, 0, 0, &err_msg);
if (rc != SQLITE_OK) {
    // Обработка ошибки
    sqlite3_free(err_msg);
}
sqlite3_close(db);
Этот код создает файл library.db и таблицу books, если её ещё нет.

Вставка данных (через подготовленное выражение):

c
sqlite3_stmt *stmt;
const char *sql_insert = "INSERT INTO books (title, author) VALUES (?, ?);";
sqlite3_prepare_v2(db, sql_insert, -1, &stmt, 0);

// Привязываем значения к параметрам
sqlite3_bind_text(stmt, 1, "Война и мир", -1, SQLITE_STATIC);
sqlite3_bind_text(stmt, 2, "Лев Толстой", -1, SQLITE_STATIC);

sqlite3_step(stmt); // Выполняем
sqlite3_finalize(stmt);
Здесь ? — это «заглушки», на место которых мы безопасно подставляем значения.

Поиск с параметром (это то, что нужно для твоей задачи):

c
sqlite3_stmt *stmt;
const char *sql_search = "SELECT title, author, year FROM books WHERE title LIKE ?;";
sqlite3_prepare_v2(db, sql_search, -1, &stmt, 0);

// Безопасно привязываем ключевое слово, добавляя %
char search_pattern[100];
snprintf(search_pattern, sizeof(search_pattern), "%%%s%%", keyword);
sqlite3_bind_text(stmt, 1, search_pattern, -1, SQLITE_STATIC);

while (sqlite3_step(stmt) == SQLITE_ROW) {
    // Читаем результаты
    const unsigned char *title = sqlite3_column_text(stmt, 0);
    const unsigned char *author = sqlite3_column_text(stmt, 1);
    int year = sqlite3_column_int(stmt, 2);
    // ... и сохраняем в нашу struct Book
}
sqlite3_finalize(stmt);
Этот паттерн — сердце твоей программы. Ты подготавливаешь запрос, 
безопасно подставляешь ключевое слово, а затем в цикле while читаешь строки и мапишь их в структуру Boo
